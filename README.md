# custom-harness-development

A test-driven SDLC agent harness on LangChain/LangGraph for Qwen2.5-Coder-7B, plus a
self-improvement loop: run the harness, keep the runs that verifiably worked, fine-tune on them
(QLoRA), measure, repeat. Built to run on Kaggle (2x T4).

```
task -> requirements -> design -> write_tests -> [test gate] -> implement (tool agent) -> review
```
Each stage sees only its declared input artifacts. The implementer never sees the tests: it
can only run them and read a sanitized pass/fail report.

## Quick start
```bash
uv sync                          # pipeline + tests (any machine)
uv sync --extra train            # + training stack (CUDA GPU)
uv run pytest                    # offline, no GPU needed (fake models)

uv run harness serve --background                  # vLLM server (needs GPUs)
uv run harness run "Write a function that merges overlapping intervals."
```

## Layout
```
configs/                 default.yaml (every setting) and kaggle.yaml (2x T4 overrides)
src/harness/
  cli.py                 `harness <command>`: one small function per command
  config.py              typed config; unknown YAML keys are rejected
  pipeline/              the SDLC graph: stages, artifacts, graph, implementer, runner, service
  tools/                 workspace jail + search / edit / patch tools for the implementer
  sandbox.py             runs code against hidden tests in a subprocess, sanitized report
  prompt_context.py      token budgets, truncation, prompt assembly, few-shot retrieval
  monitoring.py          events.jsonl and `harness report`
  serving.py             start / check / stop the vLLM server
  training_data/         seed tasks, trust filter, validation, chat-template rendering, datasets
  training/              QLoRA trainer and train-log summary
  evaluation/            held-out metrics, statistics, A/B comparison, HumanEval
  environment.py         HF / LangSmith secrets, GPU pinning
notebooks/               kaggle_pipeline.ipynb (generated by scripts/make_kaggle_notebook.py)
scripts/                 notebook generator, bundle.py (code as a Kaggle dataset)
docs/                    ARCHITECTURE.md (how it fits together), KAGGLE.md (how to run it)
tests/                   one test module per source module; all offline
```
Start with **docs/ARCHITECTURE.md** to find your way around the code.

## Commands
| Command | What it does |
|---|---|
| `serve [--background] [--adapter DIR] [--stop]` | vLLM server with tool calling and guided decoding |
| `run TASK` | the pipeline on one task |
| `generate --out DIR` | many runs over seed tasks -> `runs.jsonl` (resumable) |
| `filter --runs ... --out sft.jsonl` | keep trustworthy runs, write SFT rows |
| `validate-data --data sft.jsonl` | check rows before training (errors block training) |
| `train [--sft-data ...]` | QLoRA fine-tune; validates the data first |
| `train-report DIR` | loss curve and overfitting flag |
| `eval --out DIR` | held-out evaluation -> `eval.json` |
| `bench --mode direct\|harness` | HumanEval pass@1 |
| `compare A B` | two evaluations: intervals, paired test, verdict |
| `report DIR` | per-stage tokens, truncation, latency, tool errors |

All commands take `--config FILE` (a YAML file overriding `configs/default.yaml`).

## The self-improvement loop
```bash
harness serve --background
harness eval     --out outputs/round0/baseline       # before
harness generate --out outputs/round0
harness serve --stop                                 # training needs the GPUs
harness filter   --runs outputs/round0/runs.jsonl --out outputs/round0/sft.jsonl
harness validate-data --data outputs/round0/sft.jsonl
harness train    --sft-data outputs/round0/sft.jsonl --output-dir outputs/train0
harness serve --background --adapter outputs/train0/adapter
harness eval     --adapter outputs/train0/adapter --out outputs/round0/tuned
harness compare  outputs/round0/baseline outputs/round0/tuned
```
Round 1+ generates with the previous adapter and trains **from the base model** on all
accumulated data. On Kaggle, use the notebook instead: see **docs/KAGGLE.md**.

## What makes a run trustworthy
The model writes its own tests, so "tests pass" alone is not trusted. A run becomes training
data only if: its test suite passed the gate (valid, every requirement covered, most tests fail
against empty code), the code passes it, the review has no `[Blocker]`, it made few failed tool
calls, and its code is not a duplicate. `harness filter` prints how many runs each rule removed.

## LangSmith (opt-in)
Set `langsmith.enabled: true` and provide `LANGSMITH_API_KEY` (environment or Kaggle secret).
Every run is traced with task/sample/round metadata and scored (`tests_passed`, `trusted`, ...).
**Prompts, generated code and outputs are sent to LangSmith**; `hide_inputs` / `hide_outputs`
redact them. Local `events.jsonl` monitoring works either way.

Prompt techniques adapted (Apache-2.0) from google/elephant-goldfish-model.
